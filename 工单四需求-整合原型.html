需求说明

需求一 · 导出优化需求二 · 后台驳回原因需求三 · KYC不命中驳回

需求：工单列表 · 导出优化

范围：仅工单后台 · 工单列表「导出」。不查询彩票平台、不改列表日常操作、无性能影响。

一、改造页面与字段

页面：工单后台 → 工单管理 → 点击「导出」

点击导出时先弹出「导出选项」弹窗，运营按需勾选过滤条件后再导出。所有过滤基于工单已有的状态与备注完成，不对接彩票平台。另外，放开存款未到账工单在待处理状态下导出充值订单号的限制。

二、业务规则

（一）勾选式导出

  • 点击「导出」，弹出「导出选项」弹窗，含两个过滤开关，默认均不勾选。
  • 不勾任何项：按当前筛选与时间段正常导出全量（与现状一致）。
  • 勾选「排除已延迟成功的订单」：导出结果去掉「三方延迟成功」的工单。
  • 判定：工单状态为「已处理/已完成」且备注为系统延迟到账回调固定文案。
  • 存款文案：Deposit has been credited (previously delayed, now credited).
  • 该文案由平台延迟成功回调写入，系统固定内容、人工无法产生，可唯一识别。
  • 勾选「订单号去重」：同一充值订单号只导出一条，保留提交时间最新的一张。
  • 两个开关可任意组合，各自独立生效。
  • 弹窗内展示当前生效的筛选条件与时间段（只读提示），让运营导出前确认范围。

（二）导出充值订单号

  • 存款未到账工单（含 USDT 存款未到账）导出时，所有工单状态均带出充值订单号。
  • 现状：待处理状态导出时充值订单号为空（其他状态已带出）；本次一并放开，使所有状态一致。
  • 充值订单号取值方式不变：优先取已落库的订单号，为空时从工单提交内容中识别。

三、限制

  • 「排除已延迟成功」仅对存款未到账类工单（含 USDT 存款未到账）有意义，对其他类型该开关不产生排除效果。
  • 「订单号去重」对所有工单类型导出均可用。
  • 过滤只作用于导出结果，不改变列表展示与工单状态。
  • 不依据补单记录「本地状态(LocalState)」判断订单是否成功 —— 该字段轮询后可能未被回调更新，会漏判；一律以工单状态 + 回调备注为准。
  • 「排除已延迟成功」只排除三方延迟成功的单；客服人工办结的「已处理」工单（备注非上述文案）予以保留，因其订单未必成功。
  • 取款未到账不纳入「排除已延迟成功」（取款仅订单已完成才可提工单，无此场景）。
  • 导出充值订单号仅改导出取数，不改工单列表页展示（列表不新增充值订单号列），仅存款未到账类。
  • 导出弹窗本期仅「排除已延迟成功」「订单号去重」两项。

四、验收标准

  • 点击导出 → 弹出导出选项弹窗，两个开关默认未勾选。
  • 不勾选直接导出 → 结果与改造前完全一致。
  • 只勾「排除已延迟成功」→ 三方延迟成功的存款未到账工单不出现在结果中；客服人工办结的仍保留；已驳回的正常导出。
  • 只勾「订单号去重」→ 同一订单号只出现一条，为提交时间最新的一张。
  • 两个都勾 → 先排除延迟成功、再去重，结果为「需跟进」清单。
  • 弹窗正确展示当前筛选条件与时间段。
  • 存款未到账工单在各个状态（待处理/处理中/系统处理中/已处理/已驳回）导出，「充值订单号」均有值。
  • 尤其待处理状态导出的充值订单号从空变为有值（其他状态行为不变）。
  • 导出的充值订单号内容与工单实际提交的订单号一致。
  • 工单列表页展示不发生变化。
  • 导出的列与内容，除上述过滤外与改造前一致。
  • 非存款未到账类型导出 → 行为与改造前一致。

需求：工单 · 后台驳回原因

范围：工单配置、工单列表、工单处理弹窗、导出。

一、改造页面与字段

页面改造
工单配置 · 操作栏新增「驳回原因配置」，每站每工单类型各配一套选项
工单处理 · 单个驳回二次确认弹窗点「驳回」弹出二次确认，内含「后台驳回原因」下拉，必选一个该工单已配选项
工单列表 · 批量驳回弹窗「批量驳回」弹窗内新增「后台驳回原因」下拉，必选一个，应用到所选全部工单
工单列表状态列旁新增一列「后台驳回原因」
工单列表 · 搜索区新增「后台驳回原因」输入框，模糊搜索
工单列表 · 导出导出带出「后台驳回原因」列

新增独立字段存储所选原因，与工单现有备注（Remark）完全隔离。

二、业务规则

  • 配置：工单配置操作栏新增「驳回原因配置」，可对每个站点、每个工单类型分别维护一组驳回原因选项（新增 / 编辑 / 排序 / 启停 / 删除）。所有工单类型均开放配置，是否使用由运营决定。
  • 单个驳回：客服点「驳回」时弹出二次确认弹窗，在弹窗内从「后台驳回原因」下拉中单选并必选一个该工单类型已配置的原因，方可确认驳回。只能从预设选项中选，不可当场自定义编辑。
  • 批量驳回：「批量驳回」弹窗内新增「后台驳回原因」下拉，必选一个，选中的原因写入本次批量所选的全部工单。原选项均来自配置。
  • 展示：工单列表状态列旁展示所选原因；未选则为空。
  • 筛选：搜索区「后台驳回原因」输入框，对该字段做模糊匹配。
  • 导出：导出结果包含该列。
  • 存快照：工单保存的是所选原因的文案快照。配置项后续被修改或删除，历史工单已记录的原因文案不变。

三、限制

  • 【红线】后台驳回原因为后台专用字段，任何会员端接口（含进度查询）均不得返回、不得展示。 不得复用会员可见的现有备注（Remark）。
  • 一张工单只保留一个后台驳回原因（单选、必选）；批量驳回时全部所选工单写入同一个原因。
  • 配置与使用权限沿用现有工单配置权限，不单独新增。
  • 未配置任何驳回原因的工单类型，其驳回弹窗不显示后台驳回原因下拉，可直接驳回，不阻挡业务。

四、验收标准

  • 工单配置操作栏出现「驳回原因配置」，可对某站某工单类型新增多个原因并保存。
  • 不同站点、不同工单类型的驳回原因相互独立，互不影响。
  • 单个驳回时必须选一个已配原因才能确认；未选时「确认驳回」不可用。下拉只能选预设，无自定义输入。
  • 工单列表状态旁正确展示所选原因；未选为空。
  • 搜索框输入部分文案，能模糊匹配到对应工单。
  • 导出结果包含「后台驳回原因」列，值与列表一致。
  • 会员端进度查询及任何会员可见页面，均看不到后台驳回原因。
  • 修改或删除某配置项后，此前已记录该原因的历史工单，展示文案不变。
  • 批量驳回弹窗内必须选一个后台驳回原因，选中的原因写入所选全部工单。
  • 未配置驳回原因的工单类型，驳回弹窗不显示后台驳回原因下拉，可直接驳回。

需求：存款未到账工单 · KYC 关联不自动驳回

范围：工单配置 · 自动转发配置；自动转发回复消费逻辑。

一、改造页面与字段

页面改造
工单配置 · 自动转发配置新增开关「KYC 已连接不命中驳回关键字」，商户可配

二、业务规则

现状：存款未到账工单转发到三方 TG 群后，三方回复命中驳回类关键字时，工单被自动置为对应状态（可能驳回）。已有一个例外——工单带媒体附件且商户开启「包含媒体文件自动转待处理」时，改为转待处理（转人工）而不驳回。

  • 在「自动转发配置」中新增商户级开关「KYC 已连接不命中驳回关键字」，默认关闭。（放自动转发而非参数配置：命中驳回关键字本就是转发回复消费的逻辑，KYC 豁免是其自然延伸。）
  • 开关开启时：存款未到账工单在三方回复命中驳回关键字后，若该工单 KYC 连接状态为「已连接」，不自动驳回，改为转待处理（人工跟进）。
  • 与现有「媒体附件转待处理」（在参数配置）为或关系：工单带媒体附件、或 KYC 已连接，任一满足即不驳回、转待处理。两个开关分属自动转发/参数配置两处，逻辑上仍为或。
  • 两个条件都不满足时，维持现状按关键字配置置状态。

三、限制

  • 仅对存款未到账类工单（含 USDT 存款未到账）生效；取款不涉及。
  • KYC 关联判定以工单的 KYC 连接状态为准（已连接 / 未连接），仅「已连接」触发保护。
  • 开关默认关闭，不影响未开启该开关的商户现状。
  • 保护仅改变「命中驳回关键字后的处置」，不改变自动补单、自动转发本身的流程。

四、验收标准

  • 自动转发配置出现「KYC 已连接不命中驳回关键字」开关，可保存。
  • 开关关闭时：KYC 已连接的存款未到账工单，三方回复命中驳回关键字 → 仍按现状驳回。
  • 开关开启时：KYC 已连接的工单，三方回复命中驳回关键字 → 不驳回，转待处理。
  • 开关开启、但工单 KYC 未连接、且无媒体附件 → 仍按关键字驳回。
  • 开关开启、工单带媒体附件（媒体开关也开）→ 转待处理（现有行为不变）。
  • 命中「成功类」关键字的工单 → 正常置完成，不受本开关影响。
  • 取款未到账及其他类型 → 行为不变。
