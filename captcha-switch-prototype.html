三种方式的会员端表现
  • 不验证：表单下方无任何验证控件，填完直接提交。
  • 图形滑块验证：出现滑块条，需拖到最右端才可提交（可拖动试试）。
  • CF人机验证：出现 Cloudflare Turnstile 验证框，勾选后校验通过才可提交。
  • 未通过验证时提交按钮置灰不可点。
  • 登录与注册各自独立配置，可以是不同方式。

二、开关规则
  • 控件形态：沿用列表页既有开关的视觉语言，开关列放两个开关——「图形滑块验证」「CF人机验证」，开启为绿色，关闭为灰色。
  • 两个开关互斥：同一时刻最多只能开启一个。开启其中一个时，另一个自动关闭。
  • 都关闭 = 不验证：两个开关均为关闭状态时，表示该场景不做任何验证，会员端无验证控件。
  • 点击已开启的开关即将其关闭，此时回到「不验证」；点击未开启的开关即将其开启，另一个自动关闭。
  • 58 与 248 相互独立：登录与注册可配置为不同的验证方式，互不影响。
  • 切换后即时生效，会员端下次进入登录 / 注册页即按新配置渲染。
  • 每次切换写入后台操作日志（操作人、时间、原值 → 新值）。

四、边界与限制
#边界说明
B1CF 依赖外网CF人机验证需会员端可访问 Cloudflare 域名；对该域名不可达的地区，建议选用图形滑块验证。
B2不影响其他验证本次不涉及短信验证码、谷歌验证（Id 111 / 112）等既有开关，各自独立。
B3仅覆盖登录 / 注册找回密码、绑定手机号等其他场景的验证方式不在本次范围内。
B4仅改两条配置列表页其余配置项的名称、描述与「启用 / 禁用」交互完全不变，不做统一改造。
五、验收标准
编号场景预期结果
AC-01名称与描述Id 58 显示「开启登录验证方式 / 开启后登录将需要（图形滑块验证/CF人机验证），都关闭表示不验证」；Id 248 显示「开启注册验证方式 / 开启后注册将需要（图形滑块验证/CF人机验证），都关闭表示不验证」。
AC-02两开关互斥开启「图形滑块验证」后「CF人机验证」自动关闭，反之亦然；两者不能同时为开；页面刷新后状态保持。
AC-03登录 - 都关闭两个开关均关闭时，登录页无验证控件，账号密码正确即可登录成功。
AC-04登录 - 图形滑块登录页出现滑块，未完成滑动时登录按钮不可点；滑动完成后可正常登录。
AC-05登录 - CF人机登录页出现 Turnstile 验证框，校验通过后方可登录；校验失败给出重试提示。
AC-06注册三态Id 248 的三种组合（都关 / 滑块开 / CF开）在注册页表现与 AC-03~05 一致。
AC-07互不影响登录开启 CF人机验证、注册开启图形滑块验证时，两端各自按配置渲染。
AC-08即时生效后台切换后无需重启服务，会员端刷新页面即生效。
AC-09存量映射升级后原「启用」的站点为「图形滑块验证」，原「禁用」的站点为「不验证」。
AC-10操作日志每次切换在后台操作日志留痕，含操作人、时间、原值与新值。
AC-11其余开关不受影响列表页其他配置项的名称、描述与启用/禁用交互完全不变。
