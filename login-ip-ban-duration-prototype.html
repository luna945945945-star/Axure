二、功能描述与业务规则
🎯 核心结论
登录风控两条规则各自设置封禁分钟数，默认 30；到期自动解除该 IP 的「禁止登录」；填 0 = 永久。
到期只解除拦截、不删除记录，「风控命中账号」「封禁原因」都保留；同一 IP 再次命中，在原记录上重新封禁。
R1封禁分钟数核心
・两条规则各配各的，只能填 0 或 1~43200 的整数（43200 分钟 = 30 天），不能为空；0 = 永久。
・没配置过的站点按 30 分钟。
・该规则阈值填 0（不启用）时，封禁分钟数不起作用，照常可以保存。
・保存后只对之后新拉黑的 IP 生效；已在黑名单里的，按拉黑当时算好的解封时间走。
・保存时，系统日志在原有内容后面加「封禁分钟数：【旧值】→【新值】」。
R2拉黑核心
・解封时间 = 拉黑时间 + 命中规则的封禁分钟数；封禁分钟数为 0 时没有解封时间（永久）。
・封禁原因里写明封禁时长和解封时间；解封方式写「到期自动解封，或在本页删除该记录」，永久的写「在本页删除该记录」。
R3到期解封核心
・到了解封时间，自动解除该 IP 的「禁止登录」，最迟晚 1 分钟。
・只解除「禁止登录」，同一记录里的「禁止注册」不受影响；记录本身不删除。
・解除后，该 IP 的登录风控计数从零重新算。
・每次自动解封记一条系统日志，操作人 system。
R4再次触发
・已解封的 IP 再次命中登录风控：在原记录上重新加「禁止登录」，按当时的配置算新的解封时间；封禁原因、风控命中账号往后追加，风控类型更新为最新一次，创建时间不变。
・每次封禁时长都按当时的配置，重复触发不加长。
R5解封时间显示
・还没到期：显示解封时间；同一记录还有「禁止注册」时，后面加灰字「仅禁止登录」。
・没有解封时间：显示「永久」。人工新增的、注册风控拉黑的、封禁分钟数为 0 时拉黑的、上线前已有的记录都是永久。
・封禁类型已全部解除：灰色显示原解封时间，后面加「已解封」；「封禁类型」列显示「已解封」。
・封禁类型选「禁止登录」查询时，只查出现在还在禁止登录的记录。
R6编辑
・自动拉黑且还没到期的记录，编辑弹窗显示解封时间和剩余分钟；勾「改为永久」保存后变为永久。
・编辑时把原本没有的「禁止登录」勾上，算人工封禁，永久。
・「禁止登录」原本就有、没勾「改为永久」，保存后解封时间不变。
三、限制条件
项说明
解封精度到期后最迟 1 分钟内解除。
适用范围只有登录风控两条规则自动拉黑的「禁止登录」会到期，其他封禁都是永久。
上线默认值上线后，没配置过的站点由永久变为 30 分钟；要保持永久的站点，把封禁分钟数改成 0。
上线前的记录上线前已在黑名单里的记录没有解封时间，按永久处理。
会员提示封禁期间会员登录的提示不变，不显示剩余时间。
已解封记录一直留在列表里，不需要的手动删除。
四、开发注意事项
  1. 到期解封要同时处理黑名单缓存和列表记录：只去掉「禁止登录」，保留其他封禁类型，记录不删。
  2. 解封后清掉该 IP 的两个登录风控计数（账号数、次数），否则一解封马上又被拉黑。
  3. 解封任务每分钟跑一次；多台机器同时跑、同一条被重复处理都不能出错。
  4. 解封前再确认一次该记录的解封时间确实已到：任务读出后、动手前，运营可能已改成永久，或 IP 又被重新拉黑（解封时间变了），这两种不能解封。
  5. 前台和后台的默认值（30 分钟）要一致；老配置里没有封禁分钟数的按 30 处理。
  6. 上线顺序：先加数据库字段，再同时发前台 API、后台和解封任务。
