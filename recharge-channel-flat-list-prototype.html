背景：运营提了两件事。一是一个三方通道勾多个充值大类后，列表在每个大类下各显示一行，20 条通道挂满 5 个大类要翻 100 行；实际上数据库里就是一条通道，开关、权重、删除本来就按通道生效，这次只改展示。二是中台通道列表一屏行数太少，没有 V1 精简：现在每个格子里塞两三行「标签：值」，平均行高 85px，一屏只有 8 行左右；V1 是一列一个值、单行，一屏 17 行以上。
二、名词
名词说明
所挂大类这条通道勾选的充值大类。玩家在这些大类下都能看到这条通道。
大类内排序通道在某个大类里的前后顺序，每个大类各排各的，会同步到玩家端，决定玩家看到的通道顺序。
通道奖励通道上自定义的充值赠送比率。没有自定义时跟随大类。
生效奖励玩家实际拿到的比率，取「大类奖励」和「通道奖励」中较高的那个。同一条通道挂在不同大类下，生效奖励可能不一样。
三、功能描述与业务规则
R1列表一条通道一行
  • 每条通道只出现一次，条数和分页都按通道算。
  • 不筛选充值大类时，按通道 ID 倒序排列（新建的在上面）；筛选了某个充值大类时，只列出挂了这个大类的通道，按这个大类里的排序排列。
R2列表样式沿用现在（最小改动）
  • 列顺序：商户 → 状态 → 通道ID → 前台显示名称 / 通道名称（前台显示名称在上、加粗，点开编辑） → 充值大类 → 成功率统计 → 轮询权重 → 通道编码 → 充值通道奖励 → 其余和现在一样。单元格两行写法不变。
  • 与现在相比只动这几处：① 左侧「充值大类」列（带图标、按大类合并）去掉，改成「充值大类」文字列，放在名称列后；② 去掉「内置充值大类」列（它是按行所在大类显示的，一条通道多个大类后没有意义）；③「充值通道奖励」挂多个大类时第二行改写生效奖励区间，只挂 1 个大类时不变，见 R6。
  • 列宽按 R2-1 自适应，「充值大类」变宽的部分由「状态」「通道ID」「充值通道奖励」自适应后省下的空白抵消，第一屏能看到的列比现在多。
  • 商户列保留在最左侧，整页合并成一格。
  • 通道名称按内容自适应后完整显示；用户把列拖窄了才省略。
R2-1列宽：按内容自适应，可自由拖动
  • 打开页面时每列按当前页内容最宽的那个值给宽度，不再用代码里写死的宽度（现在「状态」「通道ID」「充值通道奖励」右侧大片空白就是写死宽度造成的）。「充值大类」默认按「相邻两个大类」最长的宽度给。
  • 表头右边缘可以拖动调宽，能拉宽也能缩窄，最小 60px；缩窄后放不下的内容省略显示，悬停看全。
  • 双击表头右边缘：这一列恢复按内容自适应。
  • 拖过的宽度按「账号 + 页面」记住，下次打开还是这个宽度（现在的列设置已经这样存，存在本机浏览器里，换电脑或换浏览器不带过去）。
R3「充值大类」列
  • 逐个列出所挂的大类名称，按「充值大类」页签的大类顺序排列，大类之间用英文逗号「,」分隔；一个大类名不会被拆到两行，只在逗号后换行。默认列宽 = 本页最长的「相邻两个大类」的宽度，所以默认大约一行两个；列宽可以拖（R2-1），拖宽一行放得更多，拖窄自动多换几行，不会压到旁边的列。挂的大类多时这一行会变高，不缩写、不概括。
  • 表头叫「充值大类」，和现在一样。大类本身已关闭的，名称后标「（已关闭）」并置灰。筛选了某个大类时，该大类名称加粗。
  • 不在这一列显示各大类的奖励（运营要求赠送比例不在通道列表展示）；大类奖励在「充值大类」页签看。
R4排序（通道ID 下方的四个按钮，位置和现在一样）
  • 上移 / 下移 / 置顶 / 置底只在查询栏选了某个充值大类后可用，排的是这个大类里的顺序，同步到玩家端；列表此时按这个大类内的顺序排列。
  • 没选大类时四个按钮置灰，悬停提示「先在查询栏选择充值大类，再调整该大类内的排序」。
  • 大类内第一条的上移 / 置顶、最后一条的下移 / 置底置灰，和现在一样。
R5开关、删除按通道生效（和现在一致，只是提示写清楚）
  • 关开关 = 这条通道在所有所挂大类下一起关；删除 = 整条通道删掉。两个确认框都写明会影响哪几个大类。
  • 只想把通道从某个大类下撤掉，到「编辑」里取消勾选那个大类。
R6充值通道奖励列
  • 奖励口径不变（已核对 uat 发放代码）：玩家在哪个大类下单，就按那个大类算，生效奖励 = max(该大类奖励, 通道自定义奖励)。同一条通道挂多个大类、没设自定义时，在各大类下分别跟各自大类的奖励走。这是合理的：玩家看到和选择的是大类，奖励是给「支付方式」的运营手段，通道只是后台路由。
  • 只挂 1 个大类：和现在完全一样。第一行「通道奖励」：自定义比率或 --，自定义不高于大类时红字「不生效」；第二行「生效奖励」：比率 + 来源标签（跟随大类 / 跟随通道），没有奖励写 --。
  • 挂多个大类：第一行同上（自定义不高于任何一个所挂大类时红字「不生效」）。第二行「生效奖励」写区间「最低~最高」，即这条通道在各个所挂大类下实际发放比率的最低值和最高值（每个大类按 max(大类奖励, 通道奖励) 算，已关闭的大类不算）；最低 = 最高时只写一个值，全是 0 写 --；不带来源标签。例：挂 A 2%、B 1%、C 0% 且没设自定义 → 0%~2%；自定义 1.5% → 1.5%~2%；自定义 3% → 3%。
  • 区间只说明范围，各大类具体生效多少 = max(该大类奖励, 通道奖励)，大类奖励在「充值大类」页签看。
R8下单限制：最大待支付单数 + 连续未支付限制（充值大类）
  • 目的：防止会员反复拉单不付款，拉低通道在三方那边的成功率。运营原需求是「上次充值成功后 M 分钟内最多 N 单，超过限制 O 分钟」；和现有「会员最大待支付单数」放一起看会懵，而且三方单要 30 分钟才超时，有待支付上限时「5 分钟 10 单」这类配置永远不会触发。所以合并成一张「下单限制」卡，两条规则分工明确。
  • ① 会员最大待支付单数 [P]（现有字段，逻辑不变）：会员在本大类同时挂着的未付单达到 P，再拉单提示「你的待支付订单数量已超出此通道限制，请前往处理」。管的是「一口气拉好几张码」。
  • ② 连续 [N] 笔订单未支付成功，暂停该会员在本大类充值 [O] 分钟（新增，0 = 不启用）：从会员上一次充值成功之后开始数，在本大类每拉单成功一笔记 1（三方下单失败没拿到付款信息的不算）；拉到第 N 笔仍没有任何一笔付成功，再拉单就暂停 O 分钟，提示「通道繁忙，请稍后再试或更换其他支付方式」，不走备用通道，可以换其他大类。管的是「拉单、等过期、再拉单」长期刷。
  • 清零：会员自己任意一笔充值成功（任意大类，含本地银行卡、USDT；不含后台人工充值）立即清零并解除暂停；暂停满 O 分钟后计数也清零重新数；会员 24 小时没在本大类拉单，计数自动清零（系统固定规则，防止几天前的零星未付累计起来误伤正常会员）。
  • 配置校验：② 的 N 和 O 要么都填 0，要么都 > 0；① 有值时 N 必须大于 P，否则会先被①拦住、②永远不触发，保存时提示。卡片下方实时逐条写出当前配置的效果；规则细节（计数口径、清零条件、超时时间对触发的影响）放在「下单限制」后的「?」里。
  • 只对三方大类生效（本地大类②不显示）；只对已上中台的站点生效。测试会员：沿用现有「会员最大待支付单数」对测试会员的处理方式，不单独区分。
  • 防误伤（通道故障、回调延迟、选错金额重拉、会员 UPI 限额满、新会员首充失败，正常会员也会连续未支付）：① 弹窗提示建议值：笔数不少于 5 笔且大于会员最大待支付单数（一般比它多 2~3 笔），暂停 10~30 分钟；配得更严（笔数 < 5 或暂停 > 30 分钟）时说明框橙字提醒，不拦保存；② 暂停提示语引导更换其他支付方式。第一期不做后台查看 / 手动解除被暂停会员（已定），所以暂停时间建议设短，误伤的会员等暂停结束即可恢复。
  • 不做：按三方返回的「支付失败」状态排除计数（各家三方是否回失败状态不一，开发量大，第一期不做）。
R9快捷金额：从其他大类复制 / 粘贴自动拆分（充值大类、提现大类）
  • 运营原话：「自动读取当前快捷按钮金额，我从其他通道复制过来，这里粘贴，直接填充下面的按钮快捷金额」。中台快捷金额在大类上，所以加在编辑充值大类「快捷金额配置」、编辑提现大类「快捷提现金额」上。
  • 从其他大类复制（快捷金额标题右侧按钮；「+ 新增金额」放在金额列表下方）：点开后选商户（本商户或同集团同币种的其他商户），在大类框里输入关键字模糊搜索（不区分大小写、忽略空格和连字符；下拉每项同时显示该大类的金额），点选大类即替换下方现有金额，不用再点按钮。充值可勾「连同赠送设置」；不勾时，金额和本大类原有某行相同的保留原赠送，新金额赠送比率 0。一步到位，不经过剪贴板。
  • 粘贴自动拆分（无按钮）：在任一金额框里粘贴含多个金额的文本（如 100,200,500,1000），从这一格开始依次填到后面的格子，格子不够自动新增，最多 12 个（提现 8 个），多出的提示没填；只粘一个金额时就是普通粘贴。分隔符：中英文逗号、空格、顿号、分号、换行；非数字和 ≤0 的忽略；重复只留第一个。适合从表格、聊天里复制一串金额过来。
  • 以上都只改弹窗里的内容，点「确定」才保存。
R10新增通道默认金额区间
  • 运营原话：「每个国家充值提现大类给一个默认通道限额区间，添加通道的时候默认填充，有需要手动改」。
  • 已定：新增充值 / 提现通道时，「金额区间」按商户币种默认填充，运营可以手动改。默认值写在代码里，不加配置页面，以后要调整让开发改。
  • 各币种默认值（待运营给值，先按下面的值开发，拿到后改前端对照表即可）：INR 充值 100 ~ 100000、提现 100 ~ 100000（参考 V1 印度站点实际配置）；PKR、BDT、MYR、BRL 等待定。没有给值的币种沿用 V1 的默认值（充值 1 ~ 5000、提现 10 ~ 30000）。
  • 为什么不照搬 V1：V1 是代码写死的 1 ~ 5000 / 10 ~ 30000，不分币种（ThirdGameApi PayTypeEntity / WithdrawTypeEntity 默认值），马来、巴西这类币值高的站点明显不合适，基本都要手动改。
  • 只在新增时预填；复制到其他商户时沿用来源通道的区间；编辑已有通道不受影响。
R11列表切换商户不清空其他查询条件（充值通道、提现通道）
  • 运营原话：「我更改商户的时候，后面的其他条件已经选的，不要变……我要批量检查一轮三方」。现在 uat 切商户会清空三方映射码、大类、币种、通道、三方商户号。
  • 改为：切商户后已选条件全部保留，直接按新商户重新查询。三方映射码、币种、状态、通道名称关键字各站点通用，原样保留。
  • 按站点各自一套 ID 的条件（充值 / 提现大类、通道 ID、三方商户号）：按名称 / 编码在新商户里找同名的一项，找到就换成新商户的那一项继续用；找不到才清空，并提示「新商户下没有同名的，已清空：xx」。
R12复制到其他商户（充值通道、提现通道）
  • 背景：集团下多个站点要接同一个新三方，三方商户号（凭证）挂在集团上只填一次，但通道要在每个站点逐条新增，10 个站点就要开 10 次弹窗。
  • 已定：不做「新增时多选商户」，新增弹窗「商户」保持单选（同现在）；只做「复制到其他商户」。
  • 入口：通道列表操作列加「复制到其他商户」，打开同一个弹窗，带出本通道全部配置（显示名称、权重、金额区间、手续费、奖励、备注等），只需勾选目标商户；新建通道状态默认「关闭」，建议各站点测通后再开。
  • 大类匹配：各站点的大类 ID 不同，先按名称自动匹配（忽略大小写、空格、连字符），在预检表里预选好；运营可以逐个商户改选 / 补选（充值多选、提现单选，选项是该商户自己的大类）。没匹配上的标红并写明「来源大类在该商户没有同名」；某商户一个都不选就跳过。
  • 自动切换通道的备用通道不复制（备用通道是各站点自己的通道），建好后到各商户单独配置。
  • 充值通道奖励（已定）：所有目标商户统一用弹窗里的奖励设置（复制时 = 来源通道的设置），不读各商户 V1 原来的比率；自定义奖励时提交前输一次谷歌验证码，对所有商户生效。后端多商户接口按「已勾修改」处理，校验一次谷歌码。
  • 动态编码通道：通道字典是「动态编码」类型时，「三方通道编码」必填。复制时带出来源通道的编码，所选商户都用这个编码（三方商户号是集团共用的，编码通常一致，判断）。没填点「确定」时，自动定位到该字段并红框提示「该通道是动态编码，必须填写」。个别商户编码不同，建好后到该商户单独改。
  • 提交前预检：复制时，点「确定」先弹出预检表，每个商户一行，列出可改选的挂载大类和预计结果（将新增 / 跳过及原因），确认后才提交（表单本身保持一屏）。提交后逐个商户独立处理，部分成功，结果弹窗列出成功几个、失败几个及原因。显示名称在目标商户已存在、或目标商户已有同一三方商户号下的这条通道（现有「支付通道重复」校验）时，该商户跳过，不自动改名。
R7编辑弹窗
  • 从列表点「编辑」不再区分是从哪个大类点进来的，弹窗内容一样。
  • 「充值通道奖励」卡片里的「生效奖励」与列表 R6 同口径：挂 1 个大类写比率 + 来源（和现在一样）；挂多个大类写区间「最低~最高」（同 R6）。勾选或取消大类、改自定义比率时实时刷新。不逐个大类列出比率。
三-B、提现通道规则
背景：① 提现通道列宽也是写死的，「状态」「通道ID」等列右侧空白缩不回去。② 提现通道表里本来就有「排序」字段，但页面上没有任何地方能改，所有通道都是 0。③ 运营对照 V1 老后台，要把 V1 有、中台没有的「今日提现状态已提交金额」补到中台，口径和 V1 一致。
W1列宽
  • 与充值通道 R2-1 完全一样：按内容自适应、可拉宽可缩窄（最小 60px）、双击恢复、按账号 + 页面记住。
W2排序（通道ID 下方四个按钮）
  • 作用：调整后台提现通道列表的显示顺序。玩家看不到提现通道，不影响玩家端；不影响自动出款（自动出款按「自动出款权重」）。附带影响：出款员审核提现单时「出款通道」下拉框也按这个顺序排（现有逻辑，不用改）。
  • 不加前置条件，和以前充值通道的箭头一样直接点：上移 / 下移和当前列表里相邻的那一行换位，置顶 / 置底移到当前列表最前 / 最后。筛选了提现大类时，只在这个大类的通道之间移动。
  • 列表默认按排序值倒序、再按创建时间倒序。存量通道排序值都是 0，所以没调过之前顺序和现在一样（按创建时间倒序）。
  • 列表第一条的上移 / 置顶、最后一条的下移 / 置底置灰；没有编辑权限看不到按钮（同充值通道）。
W4IFSC风控管理（新页签）
  • 集团维护，规则 = 11 位完整 IFSC × 三方通道；对本集团所有印度（INR）商户生效。集团下没有 INR 商户时不显示此页签。
  • 可选通道只限 INR、内置提现大类为银行卡的三方通道；非 INR 商户的提现单不比对 IFSC（巴西站点同字段存 CPF）。
  • 新增（同竞品）：选一个限制通道 + 批量粘贴 IFSC（逗号 / 空格 / 换行 / 分号分隔）；保存时转大写、去重，跳过格式非法（4 位字母 + 0 + 6 位字母或数字）和该通道已存在的，并提示跳过了哪些。比对时去空格、不区分大小写。
  • 生效：审核「出款通道」下拉里命中的通道置灰，写「该 IFSC 受限」；自动出款跳过命中通道，没有可用通道时回到人工池；提交三方前再硬校验一次（含 KYC 重提）。
  • 非 V3 模式站点由 V1 自己出款，不受此规则约束。
  • 已定：保留集团级（三方商户号集团共用，同一三方打不进某银行对所有商户都一样，配一次全集团生效，避免逐站点重复配置和漏配）。页面在提现通道下，但列表不随查询栏「商户」变化。
  • 权限：能管本集团全部印度商户的账号可以新增 / 删除；只管部分商户的账号只能查看（新增、批量删除、删除置灰并提示「需有本集团全部印度商户的权限」），避免改规则影响自己管不到的商户。
W3今日已提交（和 V1 口径一致）
  • 原「成功率统计」一列拆成两列：「今日已提交」（两行：今日已提交笔数 / 今日已提交金额，列头加问号提示写清口径）和「近1小时成功笔数」（单独一列，数据不变）。第一行沿用现在的叫法、口径改成 V1 的；金额是新增的。V1 老后台叫「今日提现状态已提交笔数 / 金额」，中台用短叫法省宽度。字号和其他列一致，每行仍是两行高。
  • 统计对象：当前仍处于「已提交」状态（已提交三方、还没收到成功 / 失败结果）、提交时间在商户本地时区今天的提现单。三方回了结果就不再计入。
  • 笔数 = 这些单的数量；金额 = 这些单的实际到账金额合计（申请金额 − 手续费），和 V1 的 RealityAmount 同口径。只算正式会员，测试会员不算。
  • 金额一律按商户法币显示，USDT 通道也显示法币；千分位 + 商户币种小数位（INR / BDT 两位；VND / IDR 零位）。只展示，不参与搜索、排序、导出。
  • 实时查当前订单，不走 10 分钟刷新的统计视图；查询失败时显示 0，不影响列表。
  • 提醒：「通道余额」是三方商户号级别的余额，同一三方商户号下多条通道（含集团内其他站点）共用一个数，不能逐行拿「余额 − 已提交金额」判断够不够。
