一、改造页面
📌 本说明书只写业务规则本身，样子和交互直接看原型，带红色 NEW 角标的是新增。
页面改动点
系统管理 → 日志 → 日志列表新增筛选「操作人」；导出带上操作人条件
二、功能描述与业务规则
🎯 核心结论
新增「操作人」输入框，操作用户包含输入内容即命中
导出带上操作人条件，导出数据与页面查询结果一致
01匹配规则核心：按「操作用户」列匹配，包含输入内容即命中，输入前后的空格忽略。操作用户带姓名后缀、带「中台_」前缀的，输入账号即可命中：
输入命中的操作用户（举例）
phillip中台_org_phillip
adminadmin（管理员）、admin_sz、中台_admin
systemsystem
02导出核心：导出带上当前填写的操作人，与其他筛选条件一起生效。
03重置：点「重置」清空操作人。
三、限制条件
项说明
匹配范围只匹配「操作用户」列，内容描述里写到的操作人不参与匹配
四、开发注意事项
  1. 页面查询、导出两处都要加操作人条件；导出是单独收集筛选条件的，别漏。
  2. 换了操作人再点「查询」要从第 1 页开始显示：页面已有“条件变了回到第 1 页”的处理，把操作人也加进去。
  3. 只按操作用户的文字匹配，不按账号 ID 查：中台账号记下的 ID 是中台自己的，会和后台账号 ID 重号；系统自动记录的 ID 是 0。
