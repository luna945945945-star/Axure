AR 钱包 · UPI 充值通道

ArUpi 充值对接流程

会员在我方页面怎么操作、我方服务端和 AR 钱包之间怎么交互、订单状态和按钮怎么变。给要接入同一个钱包的团队参考。

1三方分工

会员端、我方服务端、AR 钱包三方。钱包只提供接口，所有会员页面都由我方实现：服务端下单拿到收银台地址和 token，前端凭 token 直连钱包接口完成付款、验证和申诉。订单状态由钱包回调驱动，我方收到回调后必须反查。

2一笔充值的主流程

会员付款并在收银台提交 UTR 后，钱包核实到账再回调我方；我方反查、核对金额后上分。

建单结果怎么处理

钱包返回我方服务端会员看到
成功：返回钱包单号、收银台地址（带 token）、有效期订单记下钱包单号和收银台地址，按钮位置为「确认到账」（1）进入我方收银台页
已有在途单（下单前 queryPendingOrders 查到）不建新单，删掉这笔预订单，把在途单信息带回前端有申诉中的单：「存在一笔申诉中订单，无法再次发起充值」
isCancellable=0：「通道正在确认收款中，请耐心等待」
其他：「是否需要取消该笔订单?」，确认后取消在途单
errorCode=10000（请用推荐金额）删单，把钱包给的推荐金额带回前端弹推荐金额，选一个后重新下单

收银台由前端按收银台地址里的 token 打开我方 /arupi 页；站点开了 arUpiInputUtrSwitch 时改用 /arupi/arupi_v2，这一版没有 UTR 输入框，提交调 payWithoutUtr。收银台过期时显示「The payment order has expired」，只能返回充值页。

3在途订单

充值页选中 ArUpi 时查一次在途单（服务端转查钱包 queryPendingOrders），有在途单时每 2 秒刷新一次。钱包返回有在途单、且还没提交 UTR（utrSubmitSuccess=0）时，弹「订单未完成」，带订单号、金额和倒计时；倒计时到 0 再查一次。

4没有直接到账时

收银台里取消、过期没提交 UTR、钱包超时取消，都还有补救入口。入口在在途订单弹窗和充值记录里，显示哪个按钮由第 6 节的按钮位决定。

5订单状态流转

我方订单只有三个状态，钱包有 5 个 tradeStatus。终态只来自钱包回调，而且以反查结果为准。

回调怎么映射（以反查结果为准）

钱包回调我方订单状态按钮位
tradeStatus=1 待支付不变未申诉过 → 加 4096「可以申诉」
tradeStatus=5 申诉中不变complainedFlag=1 → 加 64「申诉中」
tradeStatus=2 已支付充值成功（上分）全部清零
tradeStatus=3 失败充值失败autoFailOrderAppealed=1 且未申诉 → 4096；已申诉且 autoFailOrderAppealed=2 → 64
tradeStatus=4 超时取消充值失败resubmitUtrFlag=0 → 加 8192「可以补提 UTR」
resubmitUtrFlag=2，或 =4 且 autoFailOrderAppealed=3按补单成功处理 → 充值成功全部清零
kycAutoConfirmView=1—置 1「确认到账」，不加 4096；其他位照常算
showRemarkAndCustomeButton=1—加 16384「显示备注和联系客服」

会员取消后钱包回调的是 3 还是 4，我方代码不区分，都按充值失败处理。

6按钮位

订单上存一个按位组合的整数（V1 叫 GroupID，中台叫 ArOrderStatus），前端只按位显示按钮，不自己判断时效。只有「待支付」和「充值失败」的订单显示这些按钮。

位含义什么时候置上会员看到点了去哪
1确认到账建单成功；回调带 kycAutoConfirmView=1「确认到账」服务端取 KYC token → 我方 KYC 页
2自动确认中KYC 通知：连上「自动确认中」点了没有反应
4KYC 重连KYC 通知：断连「KYC重新链接」同「确认到账」
64申诉中回调：已申诉且未成功（失败单仅 autoFailOrderAppealed=2）「申诉详情」申诉页（显示申诉中）
4096可以申诉回调：待支付且未申诉，或自动失败可申诉；KYC 通知：超时「我要申诉」（同时有 16384 时不显示）服务端取申诉 token → 我方申诉页

充值回调时按位从 0 重算；KYC 通知只先清掉 1、2、4，再按类型置 2、4 或 4096；订单成功后清零。

7接口清单

钱包接口都在 /ar-wallet/v4/apiCenter/ 下（客服地址除外）。服务端调用的报文一般先签名再加密，外层是 merchantCode、encryptedData、encryptedKey；noPay 例外，是明文。前端直连的请求带 token。

8对接时要注意

  • 页面我方自己做钱包只给接口。下单拿到的收银台地址里带 token，前端存下后直连钱包接口，做收银台、KYC 和申诉页。
  • 下单前先查在途单钱包按商户号加会员查在途单，同一商户下同一会员只有一笔。查到在途单就不建新单，把在途单信息带回前端，让会员继续付或取消。
  • 下单超时不能删单钱包可能已经建单。超时的单要保留，等回调来了能按单号找到它。
  • 回调只当通知解密后必须用 thirdPartyRecharge/query 反查，状态以反查为准。回调金额要等于反查金额，不等就回 FAIL。
  • 按钮位每次重算同一笔单会多次回调。回调 1「待支付」/ 5「申诉中」时订单状态不动，只更新按钮位；按钮位从 0 重算，不在旧值上加减；成功后清零。
  • 收银台过期不等于订单结束钱包订单还在时，会员可以走确认到账或申诉补救。我方定时任务和延时消息都不处理 ArUpi，只认钱包回调的「失败 / 超时取消」。
  • 失败单要能改成功超时取消后会员补提 UTR，钱包补单成功会再回调。订单要允许从「充值失败」改为「充值成功」，账变记补单。
  • 会员取消不直接改状态取消接口调成功后订单仍是待支付，等钱包回调再变「充值失败」。
  • 倒计时用钱包给的时间收银台和在途弹窗的倒计时取钱包返回的有效期，不在我方写死。
