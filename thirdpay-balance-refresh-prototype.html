一、改造页面
页面改动点
财务管理 → 支代付三方管理（三方商户列表）① 三方余额列：区分「查到余额是 0」和「没查到」；② 每行三方余额加手动刷新按钮；③ 列表上方加「自动刷新列表」开关和倒计时。其余列、筛选、新增/编辑都不改
二、名词
名词说明
三方余额三方商户号在三方那边的代付余额。由定时任务按代付通道去三方查询后写入，或运营点手动刷新查询后写入
最后更新最近一次查询成功的时间，不是最近一次发起查询的时间
查询成功三方接口正常返回，并且带了余额数值。三方返回成功但没有余额数值，按查询失败处理
三、功能描述与业务规则
01余额显示：只有查询成功才显示金额。三方返回 0 就显示 0.00，表示真的没有余额。从没查询成功过的商户，余额显示「-」，最后更新显示「--」，不能显示 0.00。
02查询失败不覆盖：定时任务或手动刷新查询失败时，余额和最后更新时间都保留最近一次成功的值，不改成 0，也不清空。最后更新时间离现在越久，说明中间查询失败越久，运营可以自己点手动刷新。
03手动刷新按钮：每行三方余额旁加一个刷新按钮，只查询这一行的三方商户。
  • 点击后按钮转圈，查询结束前不能再点；
  • 查询成功：更新这一行的余额和最后更新时间，提示「查询成功，余额已更新为 xxx」；
  • 查询失败：余额和最后更新时间不变，提示「查询失败：原因」，原因用三方或接口返回的内容；
  • 查询成功但余额低于自动关闭阈值：余额标红，提示里加一句「低于自动关闭阈值 xxx，仅提醒，不会关闭通道」。手动刷新不关闭通道、不生成预警记录、不发站内信，关闭通道仍由定时任务按阈值处理；
  • 三方商户状态为「禁用」也可以刷新。定时任务会跳过禁用的商户，所以禁用商户的余额只能靠手动刷新更新；
  • 该商户下没有代付通道（自动关闭阈值显示「未配置任何通道」）：按钮置灰，悬停提示「无代付通道，无法查询余额」；
  • 刷新成功后，顶部对应币种的汇总卡片同步更新；列表不重新排序，下次加载列表时再按排序规则排。
04自动刷新列表：
  • 列表右上方（「自定义列」左边）加「自动刷新列表」开关；打开后旁边显示倒计时「xx 秒后刷新」，每 60 秒重新加载一次列表和汇总卡片；
  • 只重新读取系统里已有的数据，不会去三方查询余额。去三方查询只有定时任务和手动刷新按钮两种方式；
  • 刷新时保留当前的筛选条件、页码、排序和滚动位置，不出现整个表格的加载遮罩；有变化的余额单元格闪一下底色；
  • 点搜索、重置、翻页、排序后，倒计时从 60 秒重新开始；
  • 浏览器切到别的页签、打开新增或编辑弹窗、有一行正在手动刷新时，倒计时暂停，并显示暂停原因；恢复后继续倒计时；
  • 默认关闭，开关状态记在当前浏览器。
05余额为「-」的商户怎么统计：
  • 汇总卡片的余额合计不算它，「低于关闭线」也不算它；
  • 关闭阈值范围选「低于阈值」或「高于阈值」时，都不显示它；
  • 填了三方余额区间时，不显示它；
  • 按三方余额排序时，升序、降序都排在最后。
06排版调整（只改本页的配置和样式，不改通用表格组件）：
  • 搜索区：宽屏（约 1536px 以上）每行 4 个条件，7 个条件加按钮正好两行；顺序为 币种、三方映射码、三方商户昵称/商户号、关联商户，第二行 状态、关闭阈值范围、三方余额区间、按钮。窄屏仍是每行 3 个；
  • 标签宽度：宽屏时每一列的标签宽度取这一列里最长的标签（如第一列只有「币种」「状态」，就很窄），去掉现在固定的 180。这样搜索区整块靠左，左边和下面的余额汇总对齐，同一列的输入框上下对齐。窄屏 3 列时，所有标签用统一宽度（取最长标签）；
  • 「三方余额区间」的输入框宽度和同一列上面的下拉框一致，左右两边都对齐；
  • 汇总卡片改成一条浅灰底的「余额汇总」：每个币种一块，用竖线分开；第一行币种和账户数，第二行余额合计（加大加粗），有低于关闭线的商户时第三行显示红色小标签「低于关闭线 N 个」（可点击，见第 07 条）。去掉蓝色边框，避免看起来像输入框；
  • 工具栏中间的「收起」是通用表格组件自带的（一起收起搜索区和汇总），所有列表页统一，不改；
  • 「自动刷新列表」开关放在工具栏右侧、「自定义列」左边。
07点「低于关闭线 N 个」筛选：
  • 只改两个筛选条件：币种只保留该币种，关闭阈值范围设为「低于阈值」；其他筛选条件（映射码、商户、关联商户、状态、余额区间）保持不变，然后立即从第一页查询；
  • 查询结果的条数应等于点击前标签上的 N（N 是按当前筛选条件统计的）；
  • 标签悬停提示「点击筛选 xx 下低于关闭线的商户」；低于关闭线为 0 时不显示标签；
  • 要恢复全部，点「重置」，或把关闭阈值范围切回「全部」。
四、开发说明（已核对中台 uat 代码）
项说明
怎么判断「-」三方商户表 Balance 默认 0，BalanceUpdateTime 默认 -1，且只在查询成功时写入。BalanceUpdateTime ≤ 0 即从没查询成功过：列表接口余额返回空，前端显示「-」
假 0PayApi 查询余额（WithdrawPayApiService.QueryBalance）里 sdkResult.Balance ?? 0：三方返回成功但没有余额会写成 0，需改为按查询失败处理
手动刷新接口新增接口，入参三方商户 ID。取该商户下任意一个未删除的代付商户通道，调 PayApi /api/Withdraw/QueryBalance（这个接口本身不校验启停状态，禁用商户可以直接查）。成功只更新 Balance、BalanceUpdateTime，不调用自动关闭通道和余额预警；失败不写库，把失败原因返回给前端
定时任务逻辑和频率都不改（仍然是成功才写、失败不写，跳过禁用商户，低于阈值自动关闭通道）
自动刷新列表前端定时调用现有列表接口，不新增接口；开关放 ProCrudTable 的 #toolbar-right 插槽
排版ThirdPartyMerchantTab.vue：search-cols 增加 xl:4；去掉 search-label-width="180"；searchColumns 里把「状态」挪到「关闭阈值范围」前面。宽屏 4 列时给每个搜索字段设 labelWidth（ProSearchBar 已支持字段级 labelWidth），值取同一列最长标签的宽度，要按当前语言测量（可复用 useAutoLabelWidth 的测量方法），窄屏用组件默认的统一自动宽度。三方余额区间的输入组宽度设为 100%；汇总只改 #table-alert 插槽里的样式。不改 ProCrudTable 组件
低于关闭线筛选用表格实例已有的方法：tableRef.setSearchParams({ currency: [币种], channelCloseBalanceCompareType: -1 })，再调 searchFromFirstPage()。注意币种搜索是多选；用代码赋值不会触发「改币种清空映射码/商户」的联动，正好符合「其他条件不变」
