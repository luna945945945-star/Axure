需求说明 · 子游戏报表-每日明细优化 2026-11-05

一、改造页面

📌 本说明只写业务规则本身，样子和交互直接看原型
页面改动点
报表管理 › 子游戏报表 › 每日明细弹窗弹窗展示完整字段；新增人均投注笔数、人均投注金额、平均每笔投注金额 3 列；导出与弹窗所见一致

二、功能描述与业务规则

🎯 核心结论
  • 每日明细共 12 列，全部一屏可见，不出现横向滚动。
  • 新增 3 个指标：人均投注笔数、人均投注金额、平均每笔投注金额。
  • 导出内容与弹窗一致，列顺序相同，导出全部日期。
1
核心新增指标的算法：人均投注笔数 = 投注笔数 ÷ 投注人数；人均投注金额 = 有效投注金额 ÷ 投注人数；平均每笔投注金额 = 有效投注金额 ÷ 投注笔数。表头分别叫「人均投注笔数」「人均有效投注金额」「平均每笔有效投注金额」。
2
分母为 0 时，该指标显示「-」。
3
3 个指标保留 2 位小数，四舍五入；金额带千分位。
4
列顺序：日期、投注人数、投注笔数、投注金额、税费、有效投注金额、派彩金额、输赢额、盈利率、人均投注笔数、人均有效投注金额、平均每笔有效投注金额。
5
核心导出的列名、列顺序、数值与弹窗完全一致（含新增 3 列）；导出当前查询条件下全部日期，不只当前页。
6
导出文件里金额、笔数、人数为数值；盈利率带 % 号；分母为 0 的显示「-」。文件名为「每日明细_游戏名_币种_起止日期」。

三、限制条件

项说明
主列表本期不新增这 3 个指标
合计行每日明细不设合计行
币种弹窗和导出的金额均为该子游戏所属币种，不做跨币种折算

四、开发注意事项

  1. 弹窗和导出用同一套列定义，以后加列、调序两边同时生效。
  2. 导出的是全部日期的数据，别只导当前页。
  3. 分母为 0 时不要出现 NaN、Infinity 或 0，统一显示「-」。
  4. 弹窗宽度随屏幕自适应；盈利率列不再固定在右侧，不遮挡其他列。
