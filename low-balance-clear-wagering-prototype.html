二、功能描述与业务规则
🎯 核心结论
会员总余额小于「打码量归零余额」时，把会员剩余打码量清为 0；归零余额填 0 = 不启用
充值后解除：下一笔充值到账时先清掉原有打码量，再加本次充值的打码量；立即解除：条件满足后系统自动清零，不用等充值
钱还在三方游戏里、或还有未结算的注单时，不清零
01总余额口径核心：总余额 = 账户余额 + 三方游戏里还没转回平台的余额；保险箱余额不算。
02清零条件核心：以下同时满足才清零：
#条件
1归零余额大于 0
2会员剩余打码量大于 0
3总余额 小于 归零余额（等于不清；例：归零余额 1，余额 0.99 清，1.00 不清）
4没有未结算的注单（彩票未开奖、三方游戏未结算都算）
03充值后解除核心：充值成功到账时，按到账前的总余额判断；满足条件就先把原有打码量清 0，再按现有规则加本次充值的打码量。线上充值、后台人工存款都算充值；彩金、红包、活动奖励到账不触发。
04立即解除核心：条件满足后，系统在 5 分钟内自动清零，不需要会员再充值。之后再充值、领奖励，按现有规则正常加打码量。
05清零留痕：每次清零记一条系统日志（操作人 system），写明会员ID、清零前打码量、当时总余额、归零时机，客服可在日志列表查到。
06输入：归零余额只能填 0 或正数，最多两位小数；默认 0，清空保存按 0 处理。归零时机默认「充值后解除」。
07和「打码量平0数」的关系：两项各自生效，互不影响。平0数看剩余打码量多少，归零余额看会员总余额多少。
三、限制条件
项说明
适用对象本站全部会员，含代理账号
币种按本站币种填写，每个站点单独配置；上线后默认 0（不启用）
已清零的打码量不恢复；之后余额回升也不补回
四、开发注意事项
  1. 总余额要把三方游戏里的钱算进去：会员最近一次把钱转进三方后还没转回平台，就当钱还在三方，不清零。只看账户余额会被钻空子（转进三方 → 清零 → 转回 → 直接提现）。
  2. 未结算注单必须排除：会员全押后余额变 0，如果这时清零，开奖赢了就能不打码直接提现。彩票未开奖要排除；三方游戏的未结算注单，以钱是否已全部转回平台为准。
  3. 充值后解除：线上充值有两套入账流程（普通模式和 V3 模式），加上后台人工存款，三处都要加，别漏。清零要在加本次打码量之前。
  4. 立即解除：用定时任务每 5 分钟跑一次，只捞「打码量大于 0 且账户余额小于归零余额」的会员再逐个判断；大站注意查询压力。
  5. 清零时要再判断一次条件，并且只把当时的打码量清掉：扫描到清零这段时间里会员可能刚充值或下注，不能把新加上的打码量一起清掉。
  6. 配置记录要同时记两项的旧值 → 新值；只改了其中一项也要记。
