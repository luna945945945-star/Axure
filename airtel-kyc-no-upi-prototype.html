原型操作提示

选一个场景后，在手机里按真实流程走：提现页选银行 → 账户列表点 Add → 填写 → Save → OTP 弹窗 Send、输码、Submit。

UPI Name 自动带入并锁定、首次绑定锁名提示、手机号校验、Slice 的 PIN、二维码与 UPI ID 比对，都是现有功能，照搬未改。

二、功能描述与业务规则
🎯 核心结论
添加 Airtel 账户只需：选 Airtel → 填手机号 → 收验证码 → 验证。验证通过后，系统用钱包返回的 UPI ID 完成绑定，会员不用填 UPI ID、不用传收款二维码
PhonePe、Paytm、Mobikwik、Slice 等其他银行的添加流程和校验完全不变
老版本 APP 仍会让会员填 UPI ID，照样能绑定成功，最终绑定的也是钱包返回的 UPI ID
01适用范围核心：只对快捷提现 UPI 里所选银行为 Airtel 的添加账户流程生效。
02Airtel 添加页核心：只保留 UPI Name 和 Phone Number 两项；UPI Name 的带入与锁定、手机号的校验照现有规则。两项填好即可点 Save 进入 OTP 验证。
03验证与绑定核心：OTP 验证通过后，直接用钱包返回的 UPI ID 生成该会员的 Airtel 提现账户；账户列表和后续出款都用这个 UPI ID。
04钱包没返回 UPI ID：本次绑定失败，不生成账户，提示会员重新验证。
05UPI ID 重复：钱包返回的 UPI ID 已被本人或其他会员绑定过，本次绑定失败，提示「This Airtel account has already been linked」。
06老版本 APP：会员仍填写 UPI ID 和二维码，照原流程提交；验证通过后同样以钱包返回的 UPI ID 为准绑定。
07绑定数量：快捷提现 UPI 账户数量上限取后台「配置管理 › 参数配置 › Fast Upi绑定数量」的值；Airtel 账户和 PhonePe、Paytm 等其他快捷提现 UPI 账户合并计数，一个会员名下所有快捷提现 UPI 账户加起来不能超过这个值。达到上限后，Airtel 在发送验证码和保存绑定两步都按现有提示拦下，不再往下走。
三、限制条件
项说明
适用范围只在快捷提现 UPI 的 Airtel；普通 UPI、银行卡等其他提现方式不涉及
提现时的 KYC 重新验证不涉及，仍按已绑定的账户验证
本次不做不向会员展示或让会员修改钱包返回的 UPI ID，账户列表只读显示
四、开发注意事项
  1. Airtel 的 UPI ID 必填要在两处同时放开：发送验证码那一步，和验证后保存绑定那一步。只放开一处，会员仍会被拦。
  2. 判断 UPI ID 是否重复，要用钱包返回的 UPI ID 去比，不能用会员提交的那个（Airtel 新流程提交的是空）。本人和其他会员的账户都要比。
  3. 钱包验证通过但没返回 UPI ID 时要拦下来，不能生成一个 UPI ID 为空的账户。
  4. 老版本 APP 会继续把会员填的 UPI ID 传上来，服务端照原来处理，不要把它当错误拦掉。
  5. 服务端先上线，客户端（APP / H5）后上线，两边不必同一天发布。
  6. OTP 弹窗里「UPI ID」那行在 Airtel 新流程没有值，要隐藏，不能显示空白。
  7. 新文案「Your UPI ID will be linked automatically after verification.」「This Airtel account has already been linked.」「Failed to get your UPI ID. Please verify again.」按站点已开放的语言补翻译。
  8. 先向钱包确认 Airtel 的银行编码写法，客户端和服务端按同一个编码判断。
