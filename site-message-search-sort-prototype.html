一、改造页面
📌 本说明书只写业务规则本身，样子和交互直接看原型，带红色 NEW / 改 角标的是新增或改动。
页面改动点
消息管理 → 公告消息 → 弹窗消息「标题」搜索改为「标题/内容」；新增「状态」筛选；列表排序调整
消息管理 → 公告消息 → 滚动消息同上；列表新增「状态」列
二、功能描述与业务规则
🎯 核心结论
「标题/内容」一个框：英语版本的标题或内容包含关键字即命中
新增「状态」筛选：全部 / 启用 / 禁用
启用的排前面，顺序与前台展示一致；禁用的排后面，按时间从新到旧
01搜索匹配核心：只匹配英语版本，即列表上显示的标题和消息内容，任一包含输入内容即命中；其他语种的标题和内容不参与。不区分大小写，输入前后的空格忽略；输入内容整体匹配，中间的空格不拆成多个词。
输入（原型数据）结果
bonus命中 ID 85、81、40、32
AVIATOR命中 ID 87（大小写不同也算）
बोनस无结果：只出现在印地语版本里
02按看得到的文字匹配核心：消息内容去掉格式标签后再匹配，图片不参与；空格、符号等转义字符按显示出来的字符匹配。
输入（原型数据）结果
span不命中：只是格式标签里的字，页面上看不到
100x命中 ID 87：红字加粗显示的 100x
02:00 to 04:00命中 ID 86
03状态筛选：全部 / 启用 / 禁用，默认「全部」。滚动消息列表新增「状态」列，显示启用 / 禁用。
04列表排序核心：
分组排序规则
启用排在最前面；排序值大的在前，排序值相同时，时间新的在前（与前台展示顺序一致）
禁用排在所有启用之后；按时间从新到旧，不看排序值
05重置：清空「标题/内容」，状态回到「全部」。
三、限制条件
项说明
匹配范围只匹配英语版本的标题和消息内容；其他语种、ID、排序值、时间不参与
排序时间即列表「时间」列
四、开发注意事项
  1. 弹窗消息、滚动消息两个页面都要改，搜索、状态筛选、排序规则两边一致。
  2. 匹配的就是列表上显示的那一版标题和内容（英语），其他语种的译文不用查。
  3. 消息内容先去掉格式标签、把转义字符还原成显示的字符，再匹配；不能拿带标签的原文直接匹配，否则搜 span、div、color 之类的词会把大量弹窗搜出来。
  4. 排序用的时间就是列表「时间」列那个时间（修改保存后会刷新）；时间也相同时再按 ID 从大到小，保证翻页不重复、不漏条。
  5. 前台展示不改。上线后抽查：后台列表启用部分的顺序 = 前台实际展示顺序，弹窗、滚动各查一次。
  6. 换条件点「查询」从第 1 页开始显示；翻页、切换每页条数时带着当前条件。
