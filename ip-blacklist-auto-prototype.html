同 IP 登录限制 & IP 黑名单改造 —— 需求说明
适用系统：V1 后台 · 系统管理 → 参数配置 / IP 黑名单　|　版本：V1.2
需求目标
  • 同一个 IP 短时间内批量登录多个账号或高频发起登录时，自动拉入 IP 黑名单并拒绝其后续登录。
  • 覆盖：批量养号与群控、撞库与暴力破解、账号枚举、脚本刷登录接口。
  • 阈值后台可配、即时生效；运营可在 IP 黑名单页查看触发依据并自行解除。
一、改造 / 新增界面与字段
1.1 参数配置页新增区块「同 IP 登录限制」新增
  • 位置：紧邻「同 IP 注册数」之上。含两条规则，各占一行、各有一个「确认保存」按钮。
规则页面文案输入项与取值范围
规则一
登录账号数量		 同一个 ip [A] 分钟内登录账号数量 >= [B] 个，直接拉入 ip 黑名单 A：时间，整数 1~1440 分钟
B：账号数，整数 1~999999 个
规则二
登录次数		 同一个 ip [C] 分钟内登录次数 >= [D] 次，直接拉入 ip 黑名单 C：时间，整数 1~1440 分钟
D：次数，整数 1~99999999 次
  • 每条规则下方以灰色小字显示随取值变化的口径回显；时间、数量、次数相关文字标红。
  • 保存后即时生效，沿用本页现有的单区块保存交互；变更自动进入现有「配置记录」页。

二、口径定义与业务规则
2.1 两条规则的统计口径
规则统计对象计数口径
规则一
登录账号数量		 窗口内尝试登录过的
不同会员账号数		 · 登录成功与失败均计入
· 同一账号多次尝试只计 1 个
· 仅统计系统中真实存在的账号，账号不存在的请求不计入
规则二
登录次数		 窗口内登录请求总次数 · 登录成功与失败均计入
· 同一账号重复登录累计计次
· 账号是否存在均计入
  • 含失败为刻意设计：撞库、暴力破解、账号枚举的绝大多数请求都是失败的，只统计成功会使规则失效。
  • 时间窗为滑动窗口：统计「距当前时刻往前 N 分钟」内的请求，精确到秒，不按整点切分。
  • 两条规则独立配置、独立计数、任一命中即拉黑，无需同时满足。两者不可相互替代——单账号反复试密码只有规则二能拦，海量账号各试一次只有规则一能拦，建议同时开启。
  • 规则开关：某条规则的两个输入框任一为 0 或留空，则该条规则不生效，另一条不受影响。
  • 不计入统计的请求：已被 IP 黑名单拦下的请求（该 IP 的计数不再增长）。
2.2 触发边界
  • 取 >= 语义：配置为 N 时，第 N 个（账号 / 次）即触发，不是第 N+1 个。
  • 例：规则一配 10，同一 IP 尝试登录第 10 个不同账号时命中；前 9 个按正常流程处理。
2.3 命中后的动作
  • 将该 IP 写入 IP 黑名单：封禁类型＝禁止登录，来源＝系统自动，创建人＝system，封禁原因按 2.4 生成。
  • 触发的那一次请求一并拒绝，即使该次账号密码正确也不发放登录态。
  • 该 IP 已有黑名单记录且不含「禁止登录」类型时（即人工添加的仅「禁止注册」记录）：为原记录补上「禁止登录」类型并在原因后追加本次触发信息，不新增记录。
  • 黑名单长期生效，无自动解除，只能由运营手动删除。
  • 不影响已登录会话：不强制下线、不中断游戏与投注，仅作用于新的登录请求。
2.4 封禁原因的生成规则（系统自动）
触发规则封禁原因文案
规则一[系统自动] 10 分钟内尝试登录 12 个不同账号（成功 2 个 / 失败 10 个），达到阈值 10 个（触发时间 2026-08-17 14:22:07）
规则二[系统自动] 5 分钟内登录请求 187 次（成功 6 次 / 失败 181 次），达到阈值 150 次（触发时间 2026-08-17 14:25:31）
补充触发在原记录的封禁原因后追加：｜2026-08-17 15:02:11 触发登录限制，补充禁止登录（…同上格式…）
  • 必含四项：触发规则与时间窗、实际值（成功 / 失败拆开）、阈值、触发时间。封禁原因只写原因，不放会员清单——会员清单在「明细」弹窗中查看，见 2.5。
  • 封禁原因在触发时一次性写入，后续不再更新。
2.5 触发明细（涉及会员）
  • 入口：IP 黑名单列表行操作的「明细」按钮。仅系统自动 / 系统补充的记录有明细，人工添加的记录无明细、按钮置灰。
区域字段说明
弹窗头部IP、触发规则、时间窗、实际值（成功 / 失败）、阈值、触发时间与封禁原因一致，便于对照
会员清单会员 ID、会员账号、尝试次数、其中成功 / 失败次数、最近尝试时间取触发时段内该 IP 上尝试登录过的会员，按尝试次数倒序
最多记录 50 个，超出时提示「仅展示尝试次数最高的 50 个」
  • 明细在触发时一次性写入，后续不再更新；删除黑名单记录时明细一并删除。
  • 用途：判断该 IP 上的是什么人——多为有充值记录的老会员 ⇒ 疑似误伤；多为新注册空号 ⇒ 养号 / 群控。这是判断误伤最直接的依据。
2.6 IP 黑名单的生效口径本次接通
  • 校验位置：登录 / 注册流程最前置，先判 IP 黑名单，再走验证码与账号密码校验。
  • 禁止登录：该 IP 的所有登录请求被拒绝，无论使用哪个会员账号。
  • 禁止注册：该 IP 的注册请求被拒绝。仅支持人工添加，系统自动拉黑不写入该类型。
  • 一条记录可同时具备两种类型。
  • 删除即解除：删除后该 IP 立即恢复；其此前的请求不再计入规则统计，等同于计数从零开始。
三、验收标准
编号场景预期结果
AC-01配置项展示参数配置页「同 IP 注册数」上方出现「同 IP 登录限制」区块，两条规则文案、四个输入框、各自的确认保存按钮完整；说明为灰色小字，时间 / 数量 / 次数相关文字标红；排版与本页其他区块一致。
AC-02保存生效修改并保存后提示成功，刷新回显新值，无需重启即时生效；变更在「配置记录」页可查。
AC-03取值校验非整数、负数、超范围（时间 1~1440、账号数 1~999999、次数 1~99999999）时提示且不保存。
AC-04规则一触发配置 10 分钟 / 10 个账号。同一 IP 依次登录 10 个不同账号（其中 8 个密码错误）：第 1~9 个按正常流程返回（成功或密码错误）；第 10 个的请求被拒绝，该 IP 出现在黑名单中。
AC-05规则二触发配置 5 分钟 / 50 次。同一 IP 发起 50 次登录请求（全部密码错误）：第 1~49 次返回密码错误；第 50 次被拒绝并进入黑名单。
AC-06单账号暴力破解同一 IP 对同一个账号连续试错 50 次：规则一计数始终为 1、不触发；规则二按次数正常触发并拉黑。
AC-07规则一去重同一账号在窗口内尝试登录 20 次，规则一计数仍为 1。
AC-08不存在的账号用系统中不存在的账号发起登录：规则一计数不增加；规则二仍按次数累计，达到阈值时正常触发拉黑。
AC-09滑动窗口规则一配 10 分钟 / 10 个账号：先登录 5 个账号，等待 11 分钟后再登录 6 个新账号，不触发（前 5 个已滑出窗口）。
AC-10触发那次一并拒绝触发阈值的那一次请求即使账号密码完全正确，也被拒绝、不发放登录态。
AC-11封禁原因完整自动拉黑记录的封禁原因包含触发规则与时间窗、实际值（成功 / 失败拆分）、阈值、触发时间四项，不含会员清单；来源＝系统自动，创建人＝system。
AC-12触发明细系统自动记录点「明细」可打开弹窗，展示 IP、触发规则、实际值、阈值、触发时间，以及涉及会员清单（会员 ID / 账号 / 尝试次数 / 成功失败 / 最近尝试时间），按尝试次数倒序、最多 50 条。人工添加的记录「明细」按钮置灰。
AC-13补充触发某 IP 已有「仅禁止注册」的人工记录，其后触发登录规则时不新增记录，而是为原记录补上「禁止登录」类型并在原因后追加触发信息，来源显示为人工添加 + 系统补充。
AC-14黑名单真正拦截黑名单中「禁止登录」的 IP，其所有登录请求被拒（含此前正常登录过的账号），提示「当前网络环境异常，请联系客服处理」。
AC-15被拦请求不计入统计IP 被拉黑后持续发起登录请求，其规则计数不再增长。
AC-16禁止注册生效人工添加且勾选「禁止注册」的 IP，注册请求被拒绝。
AC-17删除即解除删除黑名单记录后该 IP 立即恢复登录，且其删除前的请求不再计入统计（计数从零开始）。
AC-18不踢下线（已知口子）IP 被拉黑时该 IP 下已登录的会员不被强制下线，可继续投注 / 充值 / 提现。此为设计内的已知行为，验收确认符合设计即可。
AC-19换 IP 可用被拒会员切换网络后可正常登录，说明封禁对象是 IP 而非账号。
AC-20规则独立开关规则一置 0 后不再产生规则一的自动拉黑，规则二仍正常工作；反之亦然。
AC-21规则全关两条规则均置 0 时不再自动拉黑，但人工添加的黑名单仍然拦截。
AC-22来源筛选按「来源＝系统自动 / 人工添加」筛选结果正确；人工添加 + 系统补充的记录在两种筛选下均能查到。
AC-23批量清理按创建时间 + 来源筛选后可批量删除，删除后对应 IP 全部恢复。
AC-24人工新增可手动新增 IP 黑名单，封禁类型支持同时勾选禁止登录与禁止注册，封禁原因必填。
AC-25与账号锁定独立本功能不影响既有的「密码错误 N 次锁定账号」逻辑，反之亦然。
AC-26权限与日志无权限角色看不到菜单 / 按钮；人工新增、编辑、删除、批量删除均在后台操作日志留痕。
