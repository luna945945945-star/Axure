二、功能描述与业务规则
🎯 核心结论
运营填一个或多个会员ID，列表只保留「风控命中账号」里包含其中任意一个会员的 IP 记录，用来反查这些会员有没有被记在 IP 黑名单上。
只能查到 IP 被风控自动拉黑当时记录下来的会员，页面红字提示这一点。
R1输入核心
・可填多个，用英文逗号、中文逗号或空格隔开，最多 50 个，重复的只算一个；不支持账号 / 手机号。
・每个会员ID 只能是 1~10 位数字且大于 0（开头带 0 的按数值处理）；有一个不合格就整体提示格式不正确，不发起查询，列表保持原样。
・不填就不按会员ID 过滤。
R2匹配核心
・会员ID 整个相等才命中，123 不会命中 1234；多个会员ID 之间是「或」，任意一个命中，该 IP 记录就显示。
・「风控命中账号」里登录、注册两段都参与匹配；「封禁原因」文字里的会员ID 不参与。
・和 IP、封禁类型是「且」的关系；点查询回第 1 页，点重置全部清空。
R3结果显示
・满足条件的 IP 记录逐行显示，同一行只显示一次；没有符合条件的显示「无数据」。
・「风控命中账号」列预览仍最多 3 个，命中的会员排在前面并黄底高亮，个数徽章仍是该行全部个数；「查看全部」弹层里命中项黄底高亮，顺序不变。
・查询区下方常驻红字：「会员ID」只能查到：该 IP 被风控自动拉黑时，记录在「风控命中账号」里的会员。搜不到，不代表该会员没有被这个 IP 限制；是否影响登录，看「封禁类型」有没有「禁止登录」。
R4查不到的记录
人工添加的记录、没有记录会员ID 的早期记录、账号和会员ID 个数对不上的整行，以及拉黑当时查不到会员的那一项，都不会被会员ID 命中（列表上只显示账号、没有蓝色ID 的就是这类）。
R5权限
沿用本页现有查看权限，不新增权限位；会员ID 本来明文，不受「查看手机号」影响，没有该权限的角色账号仍脱敏。
三、限制条件
项说明
查询范围拉黑之后才用这个 IP 的会员，即使被拦了也查不到。
结果的含义查到只表示曾被记在该记录里，不等于现在被限制；只有「禁止注册」的记录不影响已注册会员登录。
IP 段记录IPv6 整段（如 /64）封禁，会员的实际 IP 在段内就会被限制；列表按记录显示，不按会员实际 IP 展开。
多个会员列表不区分每个会员各自命中了哪些行，也不提示哪些会员没查到。
四、开发注意事项
  1. 会员ID 整个相等才命中，不能用"包含"。命中账号是逗号分隔、登录/注册两段换行隔开的一串文字，要先拆开再比；按文字比较，不要转成整数。
  2. 账号和会员ID 两列按顺序一一对应，个数对不上的行一律当作没有会员ID，会员ID 为 0 的占位项也不参与匹配。
  3. 筛选要在分页之前做，总条数、页码与筛选结果一致。
  4. 列表结果要告诉前端「这一行命中了哪些会员ID」，用于预览排序和高亮；不按会员ID 查询时不带。
  5. 数量（最多 50 个）和格式后端也要校验；没有「查看手机号」权限时账号仍在服务端脱敏。
  6. 前后端同时上线，没有数据变更。
