需求说明

一、改造页面与入口

只改 WinGo 30秒 / 1分钟 的能量助力面板，主投注区与 3分钟/5分钟场次不动。面板状态条下方新增一条快捷条，四个入口：

  • 🎲 随机5码 从本期未投注号码中随机 5 个不重复
  • 🔁 跟上轮 复刻上一期投过的号码（去重）

另外两个入口挂在「能量排行」卡片的标题行右侧，不单独占一行——位置本身就说明它们是关于榜单的：

  • 🥇 跟 8·6·0 当前榜单前三，号码直接印在按钮上
  • ❄️ 跟 3·1·2 当前榜单后三

四个入口都只产出一组号码，金额一律走确认层的面额 / 数量。不复制上一期的金额——同号多笔、每号不同金额那套还原既复杂又容易踩三秒内重复提交；而面额在本次会话里是记住的，所以跟上轮实际拿到的总额通常和上次一样。

封盘后（剩余 5 秒起）四个全部置灰。上一期无号码投注时跟上轮置灰。第一个榜单在开局第 5 秒才出来，出来之前两个跟榜入口显示「待出榜」并置灰。

二、确认层

四个入口共用同一个确认层、同一套布局：号码球芯片（每个可删）+ 面额 / 数量 / 倍数，沿用现有下注抽屉的控件。只有右上角的重取按钮按来源变：随机是 换一批 ↻，跟榜是 按最新榜单 ↻，跟上轮没有。

主按钮必须写出金额，例如 确认 · 5码 ₹500。余额不足时按钮直接置灰写「余额不足」，不要等下单失败。

全部单期，每局都要确认。会员路径固定是两次点击：点入口 → 点确认，约 3 秒。金额记住本次会话上次用过的值，否则两次点击不成立。

三、状态横幅与倒计时

倒计时落在状态横幅右侧的芯片里，不要放在 0–9 号码球网格正中央——那个位置的裸数字读起来像第 11 个球或者开奖号。

芯片全程跟随彩票倒计时的真实剩余秒数，数值与顶部完全一致（面板会遮住顶部倒计时，芯片正好补位）。只有最后 3 秒改口播「最后助力」：

5 秒刷新不给数字。「还有 2 秒刷新」不影响用户的任何决定，「还能投几秒」才影响。刷新节奏交给前三「百分比 + 奖牌」在每次 Snapshot 的短促弹跳——规则本来就要求这个动效。

四、已锁定的规则

✓跟上轮只复制号码投注，颜色与大小不带过来
✓只复制上一期，上期没有号码投注就置灰，不追历史
✓只复制号码不复制金额，同号多笔直接去重成一个号码
✓随机只从本期未投注号码中抽；不足 5 个时按钮改成「随机3码」，为空则置灰
✓跟榜取当前已发布的榜单，确认层直接显示那三个号码，所见即所得
✓榜单未形成（开局前 5 秒、或全站无人下注）时跟榜入口置灰
✓确认层打开后若遇封盘，按钮失效并提示，绝不顺延到下一期
✓多号码一次确认 = 逐笔串行提交，不回滚；部分失败展示逐号结果并可重试
✓重试需等满 3 秒，否则会被重复提交拦截
✓能量助力本身不自动化——那是活动唯一保留的用户决策

五、为什么不做连投

方案中途讨论过「连投 N 局、每局系统自动下单」，评估后一期不做，理由是三条：

1. 加上每局确认之后，连投就等于跟上轮。连投的全部实质就是免掉那次确认；确认不能免，连投的内容就归零。

2. 它和活动目的对冲。每局那次确认是这一局里唯一强制用户回到屏幕前的动作，时点还极好——开局，第一个 Snapshot 马上要出。设 10 局走开的用户会下 50 笔注、拿 500 能量、用 0 能量、拿 0 加奖、看 0 次榜。活动层退化成自动投注器。那次确认不是成本，是节拍器。

3. 边际收益本来就不划算。随机5码已经把 15+ 次点击压到 2 次、15 秒压到 3 秒；连投再省约 3 秒，代价是授权模型、停止恢复语义、每局余额校验、部分失败即停、页面可见性处理，以及自动扣款的合规敞口。一个子系统换 3 秒。

这不是永久否决。确认层的结构留着，以后想加就是加一行「连投：本期 / 3局 / 5局」，前端两天的事。先上线看人均助力次数，健康就永远不必做；真有人抱怨 30 秒场来不及，再拿数据讨论。

六、为什么跟榜前三值得做

加奖的四个条件里，真正卡人的是「中奖号码必须在最终前三」。同样投 ₹500：随机 5 码中奖率 50%、命中后约 30% 有加奖；跟榜前三中奖率 30%、命中后约 70% 有加奖。正常派奖期望完全一样，差别全在加奖上——跟榜前三的加奖期望约 2.3 倍，综合返还率高约 1.1 个百分点。

而且它把下注和助力绑成同一个动机：你押注当前的领先者，接下来这一局就有理由去守住它们。

前三和后三必须一起上。只上前三会形成正反馈：前三被更多人下注 → 这些人拿到能量 → 能量又投给前三 → 榜单固化 → 最后三秒的隐藏反转失效。跟榜后三的用户把能量砸向冷门号，是天然的对冲。

上线后盯一个指标：前三百分比之和。从约 40% 涨到 70%，说明已经固化。

七、请运营确认

跟榜只有 3 个号码，本期能量比随机 5 码少 40%。这是策略取舍，建议不要做成「前五 / 后五」去补齐——补齐了两个入口就互相支配，玩法反而塌了。
四个入口是否一次全上。如果要分批，建议先上随机5码 + 跟上轮（解决速度问题、同时采集前三集中度基线），跟榜前三/后三放第二批。没有基线就上跟榜，榜单固化了归因不了。
后三入口的套利风险。会员可以买冷门号 + 把自己的能量全砸在其中一个上，试图把它自己推进前三。上线前请评估单用户单期能量占公共池的比重——小站点这可能真的做得到。
部分失败不回滚。5 个号码逐笔提交，中途失败已成功的不撤销，只展示逐号结果并提供重试。回滚需要后台具备撤单能力，现在没有。

八、成本提醒

这几个入口不是纯体验优化。随机5码把会员从「投 1 个号」变成「投 5 个号」，中奖号命中率从 1/10 升到 5/10，加奖触发频次上升得比投注额更快。上线前请按「快捷入口渗透率 30% / 50%」跑一遍加奖池成本模型。
